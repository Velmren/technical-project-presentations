# Core build and commands

Requirements: JDK 16 or newer, PowerShell 7, network access for the first build. The script downloads only compile dependencies into `build/deps`; Minecraft server runtime binaries are not vendored.

```powershell
./scripts/build.ps1
```

Output: `build/minecraft-npc-system-1.0.0.jar`. The reproducible default uses pinned Spigot API snapshot `1.16.5-R0.1-20210611.041013-99` (shaded) and PlaceholderAPI 2.11.7. It compiles with Java release 16, packages YAML resources, and runs the standalone core assertion suite. API libraries are not included inside the plugin JAR. Optional PlaceholderAPI is linked only after detection, so servers without it still load.

To use supplied libraries:

```powershell
./scripts/build.ps1 -ApiJar C:/deps/spigot-api-shaded.jar -PlaceholderApiJar C:/deps/PlaceholderAPI.jar
# Modern Paper compile check (plain core tests require the old Bukkit API):
./scripts/build.ps1 -Libraries C:/server/libraries -PlaceholderApiJar C:/deps/PlaceholderAPI.jar -SkipTests
```

Maven alternative: `mvn package` against the provided POM. This compiles against Spigot API 1.16.5 and provided PlaceholderAPI; the standalone suite is run by the PowerShell build script, not a JUnit Maven phase.

Install the JAR into the intended test server's `plugins` folder, then start/restart the server. Admin permission: `npcs.admin` (operators by default). Player permission: `npcs.use` (everyone by default).

| Command | Purpose |
|---|---|
| `/npcs help` | Show commands |
| `/npcs quests` | Player's active/completed state |
| `/npcs accept <quest>` | Accept configured quest with all gating checks |
| `/npcs claim <quest>` | Claim only a stage-complete quest |
| `/npcs choose <token> <index>` | Session-scoped dialogue option; normally generated by the UI |
| `/npcs list` | Configured NPCs and spawn status |
| `/npcs reload` | Validate combined YAML and reconcile |
| `/npcs create <id>` | New native villager at administrator's location |
| `/npcs remove <id>` | Remove a definition; rejected while referenced by stages |
| `/npcs set <id> <field> <value>` | Validated supported NPC fields |
| `/npcs spawn <id>` / `despawn <id>` | Persistently enable/disable definition |
| `/npcs teleport <id>` | Administrator teleports to configured spawn |
| `/npcs demo install` | Create/build dedicated `npc_demo`; teleport admin there |
| `/npcs demo install confirm` | Explicitly rebuild an existing demo, resetting blueprint blocks |
| `/npcs integrations` | Adapter/provider detection status |
| `/npcs recover <uuid> <quest> unlock` | Unlock unresolved pending claim after inspection |
| `/npcs recover <uuid> <quest> completed` | Record inspected reward delivery |

NPC editable scalar fields: `name`, `world`, `x`, `y`, `z`, `yaw`, `pitch`, `enabled`, `type`, `backend`, `dialogue`, `shop`, `permission`, `profession`, `villager-type`, `skin`, `look-radius`, `interval`, `speed`. Edit routes/graphs/rewards in YAML. Removing a referenced NPC is rejected to keep stage links valid.

The demo installer changes only world `npc_demo`; it does not reset the primary server world. It does not reset player quest progress. Rebuilding the world after completing repair quests removes those physical repairs; use a fresh test player or restore appropriate world/state backups for a fresh scenario.

Core tests cover configuration validation, disk failure and inventory algorithms. They use Java proxies, not a running Minecraft server. Network clients, rendered client screenshots, exact server distributions and optional adapter runtime results are checked separately.
