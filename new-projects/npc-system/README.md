# North Harbor / Северная гавань

Авторский Minecraft NPC System для портфолио VELMREN. Небольшой законченный сценарий: Мара принимает помощь, Лев заменяет контакты за три медных слитка, Ника проверяет сигнал, Мара выдаёт один изумруд. Персонажи и диалоги вымышлены. Клиентов, коммерческих результатов и реальных пользовательских метрик у проекта нет.

## Две реализации и их границы

- Java-плагин NorthHarbor 2.0.0: настоящие Villager NPC, Paper event bus, Adventure chat choices, проверка роли/дистанции/инвентаря, UUID-прогресс на диске.
- Браузер: независимая JavaScript-симуляция того же порядка этапов. localStorage сохраняет только demo. Медь выдаётся кнопкой; в Minecraft игрок добывает реальные слитки. Браузер не подключается к серверу.
- Остров, портреты и предметы — оригинальная SVG-иллюстрация. Это не снимок Minecraft. Плагин размещает NPC, но не строит остров, мастерскую или работающий мировой фонарь. Проверка сигнала меняет состояние задания, а не блоки мира.

## Установка плагина

Проверенная цель: **Paper 1.21.11**, API 1.21.11, Java 21 или новее. Сборка выполнена установленным JDK 25.0.2 с `--release 21`. Headless server использовал JDK 25.0.2. Не заявляется совместимость с другими версиями, Spigot или Folia.

1. Остановите свой Paper-сервер.
2. Скопируйте `north-harbor-2.0.0.jar` в `plugins/`.
3. Запустите сервер. Появится `plugins/NorthHarbor/config.yml`.
4. Администратор на ровной площадке вводит `/harbor setup`. NPC создаются на относительных координатах x=2, 5 и 8, z=0 от игрока. На неровной поверхности сначала выберите другое место или настройте offsets в config.yml и перезапустите.
5. Правая кнопка мыши по NPC открывает диалог. Голубые варианты в чате запускают команды. Действовать можно только в пределах 6 блоков от персонажа, с которым открыт разговор.

NPC неподвижны, неуязвимы и не открывают торговлю. Они используют persistent data container с ролью; сущности сохраняются самим Minecraft. Повторный setup в радиусе 32 блоков запрещён. `/harbor remove` удаляет только NPC этого плагина в этом радиусе, не меняя блоки.

## Команды

| Команда | Назначение |
| --- | --- |
| `/harbor status` | Текущий этап и переданная медь |
| `/harbor talk mara` / `lev` / `nika` | Разговор с соответствующим NPC в пределах 6 блоков; альтернатива правой кнопке |
| `/harbor accept` | Принять задание у Мары |
| `/harbor later` | Отложить принятие без изменения прогресса |
| `/harbor offer` | Передать Льву ровно один медный слиток |
| `/harbor inspect` | Проверить сигнал с Никой после трёх слитков |
| `/harbor claim` | Получить один изумруд у Мары после проверки |
| `/harbor setup`, `remove`, `reset` | Администратор: создать/удалить NPC или сбросить **своё** задание |

Административное разрешение — `northharbor.admin`, default op. Reset не возвращает предметы и намеренно позволяет администратору повторить тестовый сценарий. У обычного игрока повторная выдача заблокирована. Заполненный инвентарь не завершает задание и не теряет награду: нужно освободить ячейку и повторить.

## Сохранение

`plugins/NorthHarbor/progress.properties`: один проверенный snapshot на UUID. Схема: NEW:0 → SUPPLY:0/1/2 → INSPECTION:3 → RETURN:3 → COMPLETE:3. После каждого перехода выполняются запись во временный файл, force и атомарное перемещение; только затем обновляется память. При ошибке записи предметы не меняются, игрок получает понятное сообщение. Повреждённое сохранение отключает плагин вместо молчаливого обнуления.

Это маленький однопоточный серверный плагин без БД. Файловая система должна поддерживать atomic move; иначе шаг будет отклонён с ошибкой. На очень большом числе игроков полный snapshot-файл и синхронная запись потребуют другого хранилища. Сохранение задания и Minecraft-инвентарь **не являются общей транзакцией при аварийном выключении**: между disk commit и изменением/сохранением инвентаря остаётся окно. Exactly-once награда подтверждена для обычных действий и штатных перезапусков, не для power-loss. Удаление NPC не удаляет прогресс игроков.

## Сборка и запуск из исходников

Windows PowerShell, Node.js и JDK 21+:

```powershell
# Libraries: каталог libraries уже инициализированного Paper 1.21.11.
./scripts/build.ps1 -Libraries 'C:/path/to/paper/libraries'
# Результат: build/north-harbor-2.0.0.jar; одновременно запускаются Java unit checks.

# Подготовить static в ../../public/projects/npc-system:
./scripts/build-web.ps1
# Локальная демонстрация, только loopback:
node scripts/serve.mjs
# Открыть http://127.0.0.1:4187/projects/npc-system/
```

В интегрированной структуре source находится в `new-projects/npc-system`, static — в `public/projects/npc-system`. На обычном статическом хостинге достаточно скопировать файлы из web и JAR/README/source.zip в `/projects/npc-system/`. Внешних сервисов, аккаунтов и frontend dependencies нет. Все runtime assets локальны.

Для своего сервера: запустить Paper как `java -Xms256M -Xmx768M -jar paper.jar --nogui` из каталога сервера. Paper jar и Minecraft world не включены в release. Условия Minecraft/Paper остаются ответственностью владельца сервера.

## Проверка на 27 сентября 2026

**Java-модель: 29 assertions, PASS.** Preconditions, повторное принятие, лимит меди, преждевременная награда, разделение UUID, сериализация, перезапуск на частичном/готовом/завершённом этапе, повторная награда, сброс, повреждённые данные, сбой записи без изменения памяти.

**Реальный headless Paper: 3 полных запуска/штатных остановки, 29 assertions, PASS (13 + 11 + 5).** NorthHarbor реально загружен Paper; реальные Villager сущности, PDC, event bus и Bukkit Inventory. Проверены admin denial, 3 NPC, duplicate setup, игнорирование второй руки, правый клик и clickable choice, отказ без изменения состояния, отсутствие меди, списание ровно одного слитка, дистанция, ранняя проверка, UUID snapshot после полного перезапуска, сохранённые NPC, лишняя медь, неверная роль, полный рюкзак, реальная выдача изумруда в Bukkit Inventory, повторная выдача и повторный restart, запрет reset без разрешения, admin reset/remove.

**Тестовый игрок — controlled Java Proxy, не сетевой Minecraft-клиент.** В тестах используется настоящий Paper и inventory implementation, но client rendering, реальные packet interactions и клики Minecraft-клиента не проверены. Унаследованный локальный offline test-server привязан к 127.0.0.1; его authlib может логировать неуспешную фоновую загрузку Mojang public keys. Это не помешало runtime assertions; такой offline mode не является рекомендуемой production-конфигурацией.

Повторение headless проверки: инициализировать свой локальный тестовый сервер в `.server` с Paper 1.21.11, Paper libraries, существующим ровным flat world, свободным портом; затем `./scripts/verify-paper.ps1`. Test-only HarborVerifier после проверки убирается из plugins и не включён в release JAR. Скрипт сбрасывает **тестовый UUID** 3817551f-b41a-4c26-b034-43a46ac407da и NPC рядом с точкой 0,0. Запускать исключительно в отдельном test world, не в мире игроков.

**Браузер: 39 assertions, PASS.** Полный сценарий, ошибка отсутствующей меди, ограничение demo-ресурсов, reload в середине и после награды, выбор персонажей, reset/отмена/Escape, клавиатура, touch input, reduced motion, повреждённый и запрещённый localStorage. Размеры 1440, 1024, 850, 768, 560 и 390: без горизонтальной прокрутки. Реальные screenshots desktop/mobile/complete/error просмотрены автором. Измеренный контраст: body 10,40:1; secondary 4,83:1; primary 6,15:1; scene 7,53:1; error 6,11:1; NPC border 3,34:1. Проверки не являются полной WCAG-сертификацией. Отдельные браузеры Safari/Firefox, сетевой Minecraft-клиент и production не проверены.

## Источники API

NPC идентифицируются через [Paper Persistent Data Container](https://docs.papermc.io/paper/dev/pdc/), взаимодействие использует [PlayerInteractEntityEvent API](https://jd.papermc.io/paper/1.21.11/org/bukkit/event/player/PlayerInteractEntityEvent.html); команды и чат — [Paper plugin API](https://docs.papermc.io/paper/dev/how-do-plugins-work/). Paper/Minecraft не включены в авторскую лицензию проекта.

Проект не публиковался. Production, чужие аккаунты и редакторы платформ не использовались.
